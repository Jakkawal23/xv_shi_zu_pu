# 許氏族谱 — เว็บผังลำดับวงศ์ตระกูล

เว็บสำหรับดูลำดับวงศ์ตระกูล 許 เปิดได้ทั้งบนคอมและมือถือ ข้อมูลทั้งหมดอยู่ใน
ไฟล์ JSON แยกต่างหาก แก้ไฟล์นั้น บันทึก แล้วรีเฟรชหน้าเว็บ ก็เห็นผลทันที

## โครงสร้างไฟล์

```
xv_jia_pu/
├── index.html          ← โค้ดหน้าเว็บทั้งหมด (ไม่มีข้อมูลคนอยู่ในนี้แล้ว)
├── family-data.json    ← ข้อมูลคนในตระกูลทั้งหมด ← แก้ไฟล์นี้เวลาจะเพิ่ม/แก้ข้อมูล
└── README.md            ← ไฟล์นี้
```

`index.html` โหลด `family-data.json` ด้วย `fetch()` ตอนเปิดหน้า — ทั้งสองไฟล์
ต้องอยู่โฟลเดอร์เดียวกันเสมอ

### เรื่องสำคัญ: เปิดยังไงให้ใช้งานได้จริง

เบราว์เซอร์ (โดยเฉพาะ Chrome) **บล็อกไม่ให้หน้าเว็บที่เปิดแบบดับเบิลคลิกตรง ๆ
(`file://`) โหลดไฟล์ข้อมูลแยกได้** — เป็นข้อจำกัดด้านความปลอดภัยของเบราว์เซอร์
เอง ไม่ใช่ไฟล์เสีย ถ้าดับเบิลคลิก `index.html` แล้วเจอข้อความ "โหลดข้อมูล
ไม่สำเร็จ" นี่คือสาเหตุ วิธีเปิดให้ใช้งานได้มี 3 ทาง:

**1) ใช้ลิงก์เว็บที่ publish ไว้ (ง่ายสุด ไม่ต้องตั้งค่าอะไร)**
เปิดจากคอมหรือมือถือได้ทันที — ขอลิงก์ปัจจุบันได้จากแชทที่คุยกับ Claude
ลิงก์นี้เป็น "บันเดิล" ที่ฝังข้อมูลจาก `family-data.json` ไว้ในไฟล์เดียว
(ดูหัวข้อ "เกี่ยวกับลิงก์ claude.ai" ด้านล่าง) — ถ้าแก้ `family-data.json`
แล้วอยากให้ลิงก์นี้อัปเดตตาม ให้บอกให้สร้างบันเดิลใหม่แล้ว publish ซ้ำ

**2) รันเว็บเซิร์ฟเวอร์เล็ก ๆ ในเครื่อง (สำหรับตอนแก้ไขข้อมูลแล้วอยากดูผลทันที)**
เปิด Terminal/Command Prompt ที่โฟลเดอร์นี้ แล้วรันอย่างใดอย่างหนึ่ง:

```bash
# ถ้าเครื่องมี Python 3
python -m http.server 8000
```

```bash
# ถ้าเครื่องมี Node.js
npx http-server -p 8000
```

แล้วเปิดเบราว์เซอร์ไปที่ `http://localhost:8000/index.html`

**3) โฮสต์บน GitHub Pages** (เหมาะเพราะโฟลเดอร์นี้อยู่ใต้ `github_project`
อยู่แล้ว) — พุชทั้งโฟลเดอร์ขึ้น GitHub repo (**ตั้งเป็น private** — ดูหัวข้อ
ความเป็นส่วนตัวด้านล่าง) แล้วเปิดใช้งาน GitHub Pages ในตั้งค่า repo จะได้ลิงก์
ที่ใช้งานได้ถาวรโดยไม่ต้องรันอะไรในเครื่องเลย

## แก้ไข/เพิ่มข้อมูลคนในตระกูล

เปิด `family-data.json` ด้วยโปรแกรมแก้ข้อความ (Notepad, VS Code ฯลฯ) แล้วแก้
ตรง ๆ ได้เลย — ไฟล์นี้เป็น JSON ล้วน ๆ ไม่มีโค้ดปน แก้เสร็จบันทึก แล้วรีเฟรช
หน้าเว็บ (ผ่านเซิร์ฟเวอร์/ลิงก์ ตามหัวข้อด้านบน)

### โครงสร้างไฟล์ family-data.json

```json
{
  "meta": {
    "surname": "許",
    "title": "許氏族谱",
    "subtitle": "ผังลำดับวงศ์ตระกูล",
    "updated": "2026-09-05"
  },
  "people": [
    { "id": "p1", "gen": 1, "genLabel": "一世祖", "name": "許斌", ... },
    { "id": "p2", "gen": 2, "genLabel": "二世祖", "name": "許世", "parentId": "p1", ... },
    ...
  ]
}
```

- **`meta`** — ตั้งค่าทั่วไปของหน้าเว็บ: `surname` (ตัวอักษรในโลโก้แดง),
  `title` (ชื่อเรื่องบนหัวเว็บ), `subtitle` (คำโปรยใต้ชื่อเรื่อง), `updated`
  (วันที่ข้อมูลล่าสุด แสดงที่ท้ายหน้า)
- **`people`** — ลิสต์คนทั้งหมดในตระกูล แต่ละคนคือหนึ่ง object หนึ่งบรรทัด
  เชื่อมสายตระกูลกันด้วย `id`/`parentId`

### ฟิลด์ทั้งหมดของแต่ละคนใน `people`

| ฟิลด์ | ความหมาย | ตัวอย่าง |
|---|---|---|
| `id` | รหัสไม่ซ้ำกันของคนนี้ (ใช้เชื่อมสายตระกูล) | `"p52"` |
| `gen` | ลำดับรุ่นเป็นตัวเลข | `22` |
| `genLabel` | ป้ายรุ่นภาษาจีนต้นฉบับ | `"第二十二代"` |
| `name` | ชื่อภาษาจีน | `"許金菊"` |
| `thaiName` | ชื่อไทย (หรือ `null` ถ้าไม่มี) | `"สมชาย แซ่ฮื้อ"` |
| `order` | ลำดับการเกิด เช่น `長子` `次女` `義女` (หรือ `null`) | `"長子"` |
| `gender` | เพศ `"M"` หรือ `"F"` | `"M"` |
| `parentId` | `id` ของพ่อ/แม่ในสายนี้ (หรือ `null` ถ้าเป็นต้นตระกูล) | `"p21"` |
| `phone` | เบอร์โทรของตัวเอง (หรือ `null`) | `"0899978820"` |
| `email` | อีเมล (หรือ `null`) | `"name@email.com"` |
| `lineId` | ไอดีไลน์ (หรือ `null`) | `"line_id123"` |
| `wechatId` | ไอดีวีแชท (หรือ `null`) | `"wechat_id"` |
| `address` | ที่อยู่ (หรือ `null`) | `"123 หมู่ 4 ต.แม่สาย จ.เชียงราย"` |
| `birthDate` | วันเกิด รูปแบบ `"YYYY-MM-DD"` เป็น **ค.ศ. (Gregorian)** เท่านั้น (หรือ `null` ถ้าไม่ทราบ) | `"2001-10-08"` (8 ต.ค. 2001) |
| `deathDate` | วันเสียชีวิต รูปแบบเดียวกับ `birthDate` (หรือ `null` ถ้ายังมีชีวิตอยู่/ไม่ทราบ) | `"2020-06-15"` |
| `adopted` | `true` ถ้าเป็นบุตรบุญธรรม (義子/義女) | `false` |
| `photo` | URL หรือ data URI ของรูปภาพ (หรือ `null` = ใช้ตัวอักษรย่อแทน) | `null` |
| `notes` | รายละเอียดเพิ่มเติมแบบข้อความอิสระ (หรือ `null`) | `"ย้ายไปอยู่เชียงใหม่ปี 2540"` |
| `extra` | รายการข้อมูลอื่น ๆ ที่ไม่มีช่องสำเร็จรูป ใส่กี่รายการก็ได้ หรือ `[]` ถ้าไม่มี | ดูตัวอย่างด้านล่าง |
| `spouse` | ข้อมูลคู่สมรส — `null` ถ้าไม่มี หรือ object ที่มีฟิลด์แบบเดียวกับคนได้ (รวม `birthDate`/`deathDate` ด้วย) | ดูตัวอย่างด้านล่าง |

### วันเกิด / วันเสียชีวิต / อายุ

- เก็บ `birthDate` และ `deathDate` เป็น **ค.ศ. เสมอ** รูปแบบ `"YYYY-MM-DD"`
  (ปี-เดือน-วัน มี 0 นำหน้าเดือน/วันเสมอ) เช่นเกิดวันที่ 8 ตุลาคม ค.ศ. 2001
  ให้เขียน `"2001-10-08"` — **ห้ามใส่ พ.ศ.** ในฟิลด์นี้ หน้าเว็บจะแปลงเป็น
  พ.ศ. ให้เองตอนแสดงผล (เช่น "8 ต.ค. 2001 (พ.ศ. 2544)")
- คนที่ยังมีชีวิตอยู่: ใส่แค่ `birthDate` ปล่อย `deathDate` เป็น `null` — หน้า
  เว็บจะคำนวณ "อายุปัจจุบัน" ให้เองจากวันที่วันนี้ ทุกครั้งที่เปิดหน้า
- คนที่เสียชีวิตแล้ว: ใส่ทั้ง `birthDate` และ `deathDate` — หน้าเว็บจะโชว์
  "เสียชีวิตแล้ว" พร้อมคำนวณอายุตอนเสียชีวิตให้ ในผังต้นไม้และในหน้ารายละเอียด
- ไม่ทราบวันเกิด/วันเสียชีวิตก็ปล่อย `null` ไว้ได้ตามปกติ — จะไม่มีป้ายอายุขึ้น
  ให้ (ต้นตระกูล 19 รุ่นแรกส่วนใหญ่ไม่มีข้อมูลนี้)

### ตัวอย่าง: เพิ่มคนใหม่

คัดลอกก้อนนี้ไปแปะต่อท้ายในลิสต์ `people` ของ `family-data.json` (อย่าลืม
เครื่องหมาย `,` คั่นระหว่างคน) แล้วแก้ค่าตามจริง:

```json
{
  "id": "p52",
  "gen": 22,
  "genLabel": "第二十二代",
  "name": "許新名",
  "thaiName": "สมชาย แซ่ฮื้อ",
  "order": "次子",
  "gender": "M",
  "parentId": "p26",
  "phone": "0812345678",
  "email": "somchai@email.com",
  "lineId": "somchai_line",
  "wechatId": null,
  "address": "123 หมู่ 4 ต.แม่สาย อ.แม่สาย จ.เชียงราย 57130",
  "birthDate": "1995-03-12",
  "deathDate": null,
  "adopted": false,
  "photo": null,
  "notes": "ทำงานที่เชียงใหม่",
  "extra": [
    { "label": "เฟซบุ๊ก", "value": "facebook.com/somchai" },
    { "label": "อาชีพ", "value": "ค้าขาย" },
    { "label": "วันเกิด", "value": "12 มี.ค. 2530" }
  ],
  "spouse": {
    "name": "李美玲",
    "thaiName": "มาลี แซ่หลี่",
    "phone": "0898887777",
    "email": null,
    "lineId": null,
    "wechatId": "mali_wechat",
    "address": null,
    "birthDate": null,
    "deathDate": null,
    "extra": []
  }
}
```

สิ่งที่ต้องระวัง:

- **`id` ห้ามซ้ำ** กับคนอื่นในลิสต์ — ใช้เลขถัดจากคนสุดท้าย (ตอนนี้ไปถึง `p51`)
  ก็ปลอดภัยสุด
- **`parentId`** ต้องตรงกับ `id` ของพ่อหรือแม่ที่มีอยู่แล้วในลิสต์ ไม่งั้นคนนี้จะ
  ไม่ขึ้นในผังต้นไม้ (ลองค้นหาชื่อดู ถ้าเจอในสายบรรพบุรุษ/ผลค้นหาแต่ไม่โผล่ใน
  ต้นไม้หลัก แปลว่า `parentId` ผิด)
- ฟิลด์ไหนไม่มีข้อมูล ใส่ `null` ไว้ (ห้ามลบฟิลด์ทิ้งไปเฉย ๆ เพราะ JSON ต้องมี
  comma คั่นระหว่างฟิลด์ให้ครบ — ปลอดภัยสุดคือก็อบปี้ทั้งก้อนตัวอย่างข้างบนไปแก้)
- ถ้าพิมพ์ JSON ผิดรูปแบบ (ลืมปีกกา ลืม comma ฯลฯ) หน้าเว็บจะโหลดข้อมูลไม่ขึ้น
  เลย — เปิด Console ของเบราว์เซอร์ (กด F12) จะเห็นข้อความ error บอกตำแหน่ง
  บรรทัดที่ผิด หรือลองวางเนื้อหาในเว็บตรวจ JSON เช่น jsonlint.com เพื่อหาจุดผิด

## ค้นหา

ช่องค้นหาด้านบนรองรับ:

- **ชื่อจีนตัวเต็ม/ตัวย่อ** — พิมพ์ `许金菊` ก็เจอ `許金菊`
- **พินอิน** ไม่ต้องใส่วรรณยุกต์ เช่น `yongqing` หรือ `jin ju`
- **เบอร์โทร** ของทั้งตัวเองและคู่สมรส พิมพ์บางส่วนของเบอร์ก็เจอ
- **ชื่อคู่สมรส** ชื่อไทย อีเมล ไลน์ วีแชท ที่อยู่ หมายเหตุ และข้อมูลใน `extra`

ผลค้นหาจะกางกิ่งของผังต้นไม้ไปหาคนที่เจอให้อัตโนมัติ และถ้าเจอจากฟิลด์ที่ไม่ใช่
ชื่อ (เช่น เบอร์โทร หรือชื่อคู่สมรส) จะมีป้ายเล็ก ๆ ใต้ชื่อบอกด้วยว่าเจอจากอะไร
เช่น "คู่สมรส ชื่อ: 字在玲"

### ตัวอย่าง: ค้นหาพินอินแบบพิมพ์ผิดก็ยังเจอ

ระบบยอมให้พิมพ์พินอินผิดเล็กน้อยได้ (ตัวเกิน/ตัวขาด/พิมพ์ผิด 1-2 ตัวอักษร) ตราบใด
ที่คำค้นหายาวอย่างน้อย 2 พยางค์ขึ้นไป — ตัวอย่างเช่น ค้นหา **`xvjjinbao`**
(พิมพ์ `xv` แทน `xu` ตามคีย์บอร์ดพินอินบางระบบ บวกพิมพ์ตัว `j` เกินมา 1 ตัว)
ก็ยังเจอ **許金寶** (พินอินที่ถูกต้องคือ `xujinbao`) ได้ปกติ

ข้อจำกัด: การยอมพิมพ์ผิด (fuzzy) ใช้เฉพาะกับคำค้นหาที่ยาวตั้งแต่ 2 พยางค์ขึ้นไป
เท่านั้น — คำค้นหาพยางค์เดียวสั้น ๆ เช่น `hong` ต้องพิมพ์ให้ตรงเป๊ะ เพราะพยางค์
สั้นแบบนี้มีคำที่ใกล้เคียงกันเยอะ (`hong`, `yong`, `rong`, `long`...) ถ้ายอมพิมพ์
ผิดด้วยจะได้ผลลัพธ์เยอะเกินจำเป็น — และพินอินรองรับเฉพาะตัวอักษรจีนที่มีอยู่ใน
51 คนแรกของข้อมูลเดิมเท่านั้น คนที่เพิ่มใหม่ด้วยตัวอักษรอื่นนอกลิสต์ จะยังค้นด้วย
ชื่อจีน/ไทยตรง ๆ ได้ปกติ แต่อาจค้นด้วยพินอินไม่เจอ

## โหมดกลางวัน/กลางคืน

หน้าเว็บ**เริ่มต้นเป็นโหมดกลางวันเสมอ** ไม่ว่าเครื่องจะตั้งธีมมืดไว้หรือไม่ก็ตาม
กดปุ่มรูปพระอาทิตย์/พระจันทร์มุมขวาบนเพื่อสลับเป็นโหมดกลางคืนได้ — ระบบจะจำค่า
ที่เลือกไว้ในเบราว์เซอร์เครื่องนั้น (ผ่าน `localStorage`) เปิดครั้งต่อไปจะเป็น
โหมดที่เลือกไว้ล่าสุด

## เกี่ยวกับลิงก์ claude.ai

ลิงก์ที่ publish ไว้บน claude.ai เป็นไฟล์เว็บเพจเดียว (ไม่รองรับการแนบไฟล์
ข้อมูลแยก) จึงเป็น "บันเดิล" ที่สร้างจาก `index.html` + `family-data.json`
สองไฟล์นี้ รวมเป็นไฟล์เดียวโดยฝัง JSON เข้าไปในตัวโค้ดแทนการโหลดแยก —

- **ไฟล์ในโฟลเดอร์นี้ (`index.html` + `family-data.json`)** คือต้นฉบับที่แก้ไข
  จริง แก้ที่นี่เสมอ
- **ลิงก์ claude.ai** เป็นแค่ภาพนิ่ง (snapshot) ของข้อมูล ณ ตอนที่ publish
  ล่าสุด แก้ `family-data.json` แล้วลิงก์จะ**ไม่**อัปเดตตามเองอัตโนมัติ —

ลิงก์ที่โหลดจาก `family-data.json` ตรง ๆ อัปเดตทันทีที่พุชโค้ดใหม่ ไม่ต้องผ่าน
